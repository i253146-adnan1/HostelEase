## 1. Scope

Warden-only view of pending payment proofs; atomic Verify / Reject workflow; rejection requires a non-empty remark; verified proofs update the fee ledger; rejected proofs leave the ledger unchanged; student sees resulting status and remark on their fee page; role guards enforce warden-only access.

## 5. Business Rule Traceability

| Rule | Implementation |
|---|---|
| BR-03: Only Verified proofs update paid_amount | `verify_payment()` calls `_ledger()` only after `STATUS_VERIFIED` is set; `reject_payment()` does not touch fee record |
| NFR-02: paid = sum(Verified), remaining = max(total-paid, 0) | `_ledger()` aggregates live from DB via `Sum('amount')` on verified rows |
| FR-05: Warden sees pending proofs | `list_pending_payments()` → `pending_payments_list` view → `warden_pending_payments.html` |
| FR-06: Warden verifies / rejects with remark | `verify_payment()` / `reject_payment()` → view actions behind `@warden_required` |
| NFR-01: Role enforcement | `@warden_required` on all three warden views; student gets HTTP 403 |
