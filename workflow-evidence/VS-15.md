## Architecture & Decision Summary
- **Governance (`decision-log.md`, Log 28 — Resolves OQ-30):**
  - **One Open Leave Request per Student (OQ-30):** One open leave request per student is enforced, where open means status `PENDING` or `APPROVED` — this aligns `AGENTS.md`'s existing instruction with PRD `OQ-30` and closes it formally. A student with an existing `PENDING` or `APPROVED` `LeaveRequest` cannot submit another (`EC-48` / `AC-17.3`). A student with only `REJECTED` history may submit again.
  - **No Student-Initiated Cancel Action (Flagged for Client/TA Confirmation):** `AC-17.1–AC-17.4` do not describe any student-initiated cancellation/withdrawal of a leave request (unlike Room Requests in VS-11). Therefore this slice does **not** implement a cancel action for leave requests. Flagged as worth raising with the client/TA if a cancel capability is later wanted.
  - **BR-12 / BR-05:** Warden approval or rejection updates only the `LeaveRequest` row and never modifies `Student.status`, `RoomAssignment`, or login/session access. Records are never hard-deleted.
- **App Placement (`operations`):**
  - Placed in `operations` alongside other student-submitted operational workflows (`Feedback`, `Complaint`, `StoredFile`), preserving physical separation from `hostel` (`Student`, `RoomAssignment`).
- **Model (`operations/models.py`, migration `operations/migrations/0004_leaverequest.py`):**
  - `LeaveRequest`: `student_id` (`CharField(max_length=50, db_index=True)` — logical `Student.student_id`, no cross-module FK), `departure_date` (`DateField`), `return_date` (`DateField`), `reason` (`TextField`), `status` (`PENDING`, `APPROVED`, `REJECTED`), `warden_remark` (`TextField`, `null=True, blank=True`), `created_at`, `updated_at`, `decided_by_warden_at` (`DateTimeField`, `null=True, blank=True`). Ordering: `['-created_at', '-id']`. `delete()` raises `PermissionError` (BR-05).
- **Module Boundary & Service Layer (`operations/leave_service.py`):**
  - Validates active students via `hostel.student_service.StudentService.validate_active_student()` without querying `Student` directly.
  - `submit_leave_request(student_id, departure_date, return_date, reason)`, `decide_leave_request(request_id, warden_decision, remark=None)`, `get_pending_count()` (ADR-005 read-only interface for future Dashboard), `list_student_leave_requests(student_id)`, `list_pending_leave_requests()`, `list_decided_leave_requests()`, and `LeaveService` facade.
- **Views, URLs & Templates (`operations/views.py`, `operations/urls.py`, `templates/operations/`, `templates/base.html`):**
  - Student views (`student_leave_requests`, `student_leave_request_create`) guarded by `@student_required` and `_get_active_student_id(request)` (strict ownership, no cancel button).
  - Warden views (`warden_leave_requests`, `warden_decide_leave_request`) guarded by `@warden_required`.
